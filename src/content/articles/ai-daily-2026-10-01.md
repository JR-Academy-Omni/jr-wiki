## 1. GPT-6.1 Sol上线API：价格是Astra的五分之一

![AI模型](https://images.unsplash.com/photo-1677442136019-21780ecad995?w=800&q=80)

**一句话**：OpenAI在9月29日的DevDay上发布GPT-6.1 Sol。API文档给出的价格是每百万token输入2美元、缓存输入0.1美元、输出10美元，上下文窗口1,050,000 token，单次最多输出128,000 token。

昨天的日报讲了dots，那是面向ChatGPT用户的产品。对开发者来说，DevDay上更实际的是这个模型。OpenAI对它的定位写在模型页第一句：以更低成本，在复杂编程、电脑操作和专业工作上做到“near-Astra performance”。开发者社区的官方汇总帖说得更直接：标准token价格是Astra的五分之一。BGR的独立报道也写的是“20% of Astra's token price”。

我的看法：五分之一的价差足够让很多团队重新算账。现在跑GPT-6 Astra的代码审查、文档抽取这类批处理任务，成本大头在输出token。换到Sol后单价降下来，但“接近Astra”是OpenAI自己的基准结论，在你的任务上差多少，只能自己测。

几个参数值得记一下：知识截止日期是2026年4月30日；reasoning effort有low、medium（默认）、high、xhigh、max五档。评测时建议固定同一档，只换模型，不然对比没意义。

**实操建议**：从生产日志里抽50到100个真实请求，分别用Astra和6.1 Sol各跑一遍，同时记下通过率和单任务成本。通过率掉得不多，就先把批处理任务切过去；对延迟敏感、出错代价高的链路暂时别动。

还没确定的：OpenAI在博客里列出的DeepSWE、GDP.pdf等基准成绩，我们这次没能直接打开原文逐条核对（openai.com返回403），所以本文不引用具体分数。

> 一手原文：“GPT-6.1 Sol delivers near-Astra performance at a lower cost for complex coding, computer use, and professional work.”
>
> “improves coding and computer use, with standard token prices at one-fifth of Astra's”
>

## 2. Agents API公测：Codex的agent底座开放出来

![开发者](https://images.unsplash.com/photo-1555066931-4365d14bab8c?w=800&q=80)

**一句话**：Agents API在DevDay进入公测。官方文档说它让应用“通过OpenAI托管的API访问Codex harness”：会话、编排、上下文压缩和恢复归OpenAI管，工具和执行环境由你的应用决定。

做过长任务agent的人都知道，难点通常不在调模型。难的是跑到第40步时上下文爆了怎么压缩，进程挂了怎么从断点接着跑，多轮之间的状态存在哪。过去这些都得自己写，或者靠开源框架拼。Agents API把这层做成托管服务，用的是OpenAI自己在Codex里跑过的那套。

执行环境有两种选择：OpenAI托管的沙箱，或者接你自己基础设施里的沙箱。agent在沙箱里可以执行代码、改文件、连MCP服务器、产出文件。The Next Web报道说，Agents API现在也支持电脑操作，agent可以在OpenAI托管的浏览器里操作软件，还带来了Codex里用的多agent工具、工具搜索和上下文压缩。

计费没有单独的平台费。文档原文：模型按所选模型的API费率，OpenAI工具按标准费率，托管沙箱按标准容器费率。这意味着长会话的成本主要看token，自动压缩上下文能省多少，得实测。

**实操建议**：请求头要带`OpenAI-Beta: agents=v1`，说明接口还在beta，字段可能会变。生产环境先用在内部工具上，别直接接给客户；同时把工具权限收窄，尤其是能写数据库、发外部消息的那几个。

还没确定的：公测期的速率限制、正式版时间和SLA，文档里没有写明。

> 一手原文：“The Agents API gives your application access to the Codex harness through an OpenAI-managed API.”
>
> “OpenAI manages sessions, orchestration, context compaction, and recovery while your application provides tools and chooses its execution environment.”
>
> 来源：[OpenAI API · Agents API概览](https://developers.openai.com/api/docs/guides/agents-api/overview) · [The Next Web独立报道](https://thenextweb.com/news/openai-bedrock-managed-agents-aws-devday)

## 3. AWS上线Bedrock Managed Agents：OpenAI agent跑在你的AWS里

![云计算](https://images.unsplash.com/photo-1451187580459-43490279c0fa?w=800&q=80)

**一句话**：AWS在9月29日发布Bedrock Managed Agents（BMA）预览。按AWS公告，它基于为AWS原生定制的OpenAI Agents API，由AWS和OpenAI共同打造；The Next Web报道称所有推理跑在Amazon Bedrock上，客户数据不离开AWS。

这条和第2条是同一套底座的两个出口：想要最省事的，直接用OpenAI的Agents API；数据合规要求必须留在自己云账号里的，走Bedrock。

对企业来说，关键是治理能力。AWS公告写明：每个agent有自己的IAM角色，关键操作前可以要求人工审批，支持的API活动会记进CloudTrail。审计团队最常问的“这个agent以谁的身份、做了什么”，这套设计能直接回答。

价格方面，预览期除了agent消耗的底层AWS资源，不额外收BMA费用。区域目前是美国东部（弗吉尼亚北部、俄亥俄）和美国西部（俄勒冈）三个区域。

**对澳洲读者**：悉尼区域不在预览名单里。数据必须留在澳洲境内的项目，现阶段还用不上。备考AWS认证、做云架构的同学，可以先读文档，了解IAM角色加CloudTrail这套agent治理思路。以后面试被问到“怎么审计AI agent”，这是一个现成的参考架构。

还没确定的：正式版价格、上线时间和更多区域，公告都没有给出。

> 一手原文：“Bedrock Managed Agents (BMA) is built on a customized version of OpenAI's Agents API engineered to be AWS-native”
>
> “During preview, there is no additional charge for BMA beyond the underlying AWS resources your agents consume.”
>
> 来源：[AWS What's New公告](https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-managed-agents-preview/) · [The Next Web独立报道](https://thenextweb.com/news/openai-bedrock-managed-agents-aws-devday)
